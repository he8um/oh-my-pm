## Publication gates that were satisfied

- **Dry run first.** Run
  [30760386758](https://github.com/he8um/oh-my-pm/actions/runs/30760386758) ran
  with `publish=false`: prepare and all three installed-qualification jobs
  succeeded, the publish job was **skipped**, and **no tag and no release were
  created** — verified afterwards against `git ls-remote --tags origin`,
  `gh release view v0.6.0` (not found), and `releases/latest` (still `v0.5.4`).
- **Exact version gate.** The workflow refuses any `version` other than `0.6.0`,
  enforced in both the prepare and publish jobs.
- **Exact confirmation gate.** `publish=true` requires
  `confirmation == "RELEASE v0.6.0"`, enforced twice.
- **Immutable base lineage.** The workflow verified that `v0.5.4` still resolves
  to `288337a9514150b7a5973d9d9410f7186567520f` and remains a non-draft,
  non-prerelease before building on top of it.
- **Protected environment.** The publish job is gated on the `github-release`
  environment (branch policy + required reviewer `he8um`). Approval was recorded
  for run 30760849237 before the job started.
- **No overwrite.** The workflow refuses to run if the tag or release already
  exists. No asset was ever overwritten.
- **No registry publication.** No `npm publish`, `pnpm publish`, or
  `cargo publish` anywhere in the workflow; every package remains private.

Job results for the publish run: prepare `success`; installed qualification
`ubuntu-latest`, `macos-latest`, `windows-latest` all `success`; publish
`success`.

## Behaviour statement

`v0.6.0` changes the invoked command names and nothing else. Product name,
package scope `@oh-my-pm/*`, environment prefix `OH_MY_PM_*`, the `.oh-my-pm/`
and `~/.oh-my-pm/` data directories, the `lib/oh-my-pm/versions/<version>/`
install layout, the `oh-my-pm-v<version>` archive names, and the `oh-my-pm` MCP
server key are all unchanged. Project Brain schema 1 and Project Memory store
format 2 are unchanged, so **no data migration is required**. No command was
added or removed, no JSON schema or Markdown structure changed, no exit code
changed, and no MCP tool, schema, annotation, or ordering changed. No Dashboard,
HTTP server, or write capability exists.

## Rollback and fix-forward

`v0.6.0` is immutable. The tag is never moved, assets are never overwritten, and
this record is never rewritten. A defect is corrected by publishing a later
patch on the v0.6 line, which re-points `latest` through the same gated workflow.
Both alias families remain installed, so a consumer that has not migrated is
unaffected by any such patch.
