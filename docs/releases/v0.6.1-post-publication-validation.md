## Publication gates that were satisfied

- **Dry run first.** Run
  [30795724210](https://github.com/he8um/oh-my-pm/actions/runs/30795724210) ran
  with `publish=false`: prepare and all three installed-qualification jobs
  succeeded, the publish job was **skipped**, and **no tag and no release were
  created**. Verified afterwards: `git ls-remote --tags origin` reported the same
  12 tags as before the run, `refs/tags/v0.6.1` had zero entries,
  `gh release view v0.6.1` reported "release not found", and `releases/latest`
  still resolved to `v0.6.0`.
- **Exact version gate.** The workflow refuses any `version` other than `0.6.1`,
  enforced in both the prepare and publish jobs.
- **Exact confirmation gate.** `publish=true` requires
  `confirmation == "RELEASE v0.6.1"`, enforced twice.
- **Immutable base lineage.** The workflow verified that `v0.6.0` still resolves
  to `34642c4fe121c34c65f80a08b3e75560099676ff` and remains a non-draft,
  non-prerelease before building on top of it. That base advanced from `v0.5.4`
  as part of this release; the superseded base SHA was removed rather than left
  alongside, and `tools/test/v0.6-release-qualification.test.mjs` now asserts its
  absence so a half-finished promotion fails.
- **Protected environment.** The publish job is gated on the `github-release`
  environment (branch policy + required reviewer `he8um`). Approval was recorded
  for run 30796527226 before the job started.
- **No overwrite.** The workflow refuses to run if the tag or release already
  exists. No asset was ever overwritten.
- **No registry publication.** No `npm publish`, `pnpm publish`, or
  `cargo publish` anywhere in the workflow; every package remains private.

Job results for the publish run: prepare `success`; installed qualification
`ubuntu-latest`, `macos-latest`, `windows-latest` all `success`; publish
`success`.

## Secret and local-path scan

A scan of the extracted tree for realistic GitHub token forms (`ghp_` and
`github_pat_` followed by at least twenty token characters), AWS access key ids,
PEM private-key headers, and this machine's developer path found **no match of
any kind**.

The v0.6.0 record listed three benign matches for the same class of scan. They do
not reappear here because the patterns above require realistic token lengths
rather than a bare prefix, so OMP's own redaction marker list and a third-party
PEM *format* check are no longer flagged. Nothing about the bundle contents
changed in that respect.

## Installed qualification against the downloaded artifact

The downloaded bundle was installed into a clean temporary prefix with
`omp-install.mjs --apply`, which reported `applied` at version `0.6.1` and wrote
**twelve shims** — six commands, each with a POSIX and a Windows `.cmd` launcher.

Alias behaviour from the installed shims:

- `ohmypm` emits `Warning: \`ohmypm\` is a compatibility alias; use \`omp\`.`
- `oh-my-pm` emits `Warning: \`oh-my-pm\` is deprecated; use \`omp\`.`
- both notices go to **stderr only**, exactly once per invocation.

### The application boundary convergence, verified on the public artifact

This is the release's central change, so it was checked against the installed
binary rather than a local build. `omp brief <fixture> --json` from the installed
prefix:

- exits `0` with empty stderr;
- emits the unchanged public envelope `{id, ok, data, trace}` with `id: cli-brief`;
- is **byte-identical** to the corresponding entry in
  `tests/fixtures/public-golden.json`, which was recorded from the v0.6.0 tree
  **before** any refactor began.

So the CLI now routes the shared local workflows through
`runLocalProjectWorkflow` — composing no Runtime, provider, or Kernel of its own
for them — and the observable output did not move by a single byte.

Alias stdout parity on the same invocation: `omp`, `ohmypm`, and `oh-my-pm`
produce byte-identical stdout, so a piped `--json` call stays parseable through
any of the three families.

## Conclusion

`v0.6.1` is published as the latest stable release, is public, non-draft, and
non-prerelease, targets the exact merge commit of its implementation PR, and its
downloaded assets verify by checksum and pass installed qualification on this
machine in addition to the three-platform matrix run in CI.

The release changed the internal architecture and provably changed nothing a user
or an MCP client can observe.
