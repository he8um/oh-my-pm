# OH MY PM v0.2.0-rc.1 — Post-Publication Validation

## Purpose

Validate the published `v0.2.0-rc.1` prerelease the way a real user would consume
it — installed from the public GitHub Release rather than from the repository
source tree — and produce a stable GO / NO-GO recommendation. This is a
read-only validation phase: no features, architecture, providers, MCP tools, or
Kernel behavior were changed, and no stable release was prepared or published.

## Governance Observation

The published `github-release` environment exists but has **no required-reviewer
protection rule** — only a branch policy (custom branch policies) is configured,
and administrators may bypass. This is why the publication run proceeded to
completion without pausing for a manual approval gate.

- Classification: release-governance finding, **not** a product defect.
- Severity: recommended before stable; non-blocking for RC runtime validation.
- Recommendation: add at least one required reviewer to the `github-release`
  environment before publishing stable `v0.2.0`. No repository settings were
  changed during this phase (that requires separate approval).

## Defects

No Blocker, High, or Medium findings.

Low (documentation / non-blocking UX):

- **L1 — No `--help` surface.** `oh-my-pm --help` and `oh-my-pm help` return
  `OMP-C-3002` / `OMP-C-3001` (exit `2`). The CLI has a defined, documented
  command surface (`status`, `brief`, `risks`, `next`, `handoff`,
  `providers …`, `github …`), but offers no conventional `--help`. Error UX is
  otherwise clean (coded, no leaks). Follow-up: consider adding a `--help`/`help`
  surface.
- **L2 — No installed MCP client-config generator.** Generating a client config
  relies on a repository-only script; the installed release has no equivalent
  command. Future distribution/UX opportunity.
- **L3 — Release-environment reviewer gap.** The `github-release` environment has
  no required reviewer (see Governance Observation). Recommended before stable.
- **L4 — Stale fixture path in docs.** Roadmap references
  `examples/fixtures/markdown-project`; the bundle ships the fixture at
  `examples/markdown-project`. Documentation-only.

All core user journeys — public-artifact installation, source independence,
